# 🎈 Воздушный полет — бонусная crash-игра

Прототип бонусной crash-игры с турнирной механикой для «Столото».
Чемпионат России по продуктовому программированию. **Версия 2.1.0.**

---

## 1. Быстрый старт

Требования: **Java 17+**, никаких зависимостей и сборки.

```bash
# в папке с файлами:
java BalloonGame.java          # → http://localhost:8080
java BalloonGame.java 9090     # другой порт
```

Открыть **http://localhost:8080** и играть. Конфиг/база создаются автоматически
(`config.json`, `users.json`). Если рядом лежит скомпилированный `BalloonGame.class`
от старой версии — удалите его.

**Вход:** регистрация по email + пароль (от 4 символов) или
**админ: `admin@mail.com` / `12345678`** (вход admin@mail.com работает всегда,
сервер сам создаст/починит запись; старый логин `admin` тоже пускает).
Сессия — токен в localStorage, переживает перезапуск сервера.

**Локальный режим:** если открыть `index.html` без сервера, игра работает
в браузере (математика в JS), но без входа, ассетов с диска и общей базы.

## 2. Архитектура

| Файл | Роль |
|---|---|
| `BalloonGame.java` | Сервер: HTTP (JDK `HttpServer`), вся математика, пользователи, конфиг, автообнаружение ассетов. Однофайловый: встроенная копия фронта позволяет запуск вообще одним файлом |
| `index.html` | Весь фронт: 4 экрана, анимации, звуки (WebAudio-синтез + файлы), крутилки, зоны, автоскейл |
| `assets/` | Все картинки/звуки/видео/шрифты — подхватываются **по имени файла**, без правки конфига |
| `config.json` | Игровые параметры (создаётся при первом сохранении из админки) |
| `users.json` | Аккаунты: баланс, очки, пазлы, сессии (переживает перезапуск) |

Real-time: polling состояния раунда каждые 250 мс (≤1 с по ТЗ). БД нет —
прототип в памяти + JSON-файлы.

## 3. Экраны и пользовательский путь

1. **Вход/регистрация** — стеклянная карточка над фоном `bg-auth`, валидация email,
   понятные ошибки под формой.
2. **Выбор темы** — два больших парящих шара: 🔴 красный (12 уровней) /
   🟢 зелёный (9 уровней), площадка снизу, облака и птицы.
3. **Ставка** — три колонки: слева *История ставок* (все игроки + лента взрывов),
   по центру *сумма + бустер + «Начать полёт» + шар темы + последний взрыв*,
   справа *Лидерборд* (таймер дня, вкладки День/Всё время, призы).
4. **Полёт** — шар поднимается, коэффициент растёт, уровни проявляются по мере
   подлёта, кнопка «Забрать» активна сразу после ×1.00.
5. **Результат** — выигрыш/потеря, очки, пазлы, «могли бы забрать больше»,
   кнопка «Подарок» (если хватает пазлов), «Играть снова», автовозврат к темам
   через 10 с (настраивается).

## 4. Все механики

### 4.1 Ставка
Свободная сумма бонусов (от `min_bet` до баланса) + выбор бустера из списка
`boosters` (чипы ×1…×N; в админке можно ×10, ×100 и т.д.). Подсказка считает
выигрыш на лету: «Выигрыш = 100 × коэффициент × 3 (бустер)». Недостаточно
бонусов — кнопка старта заблокирована.

### 4.2 Полёт и cashout
- Коэффициент растёт по кривой `m(t)=1+g·t^p` (по умолчанию очень плавно:
  ×2 на ~19-й секунде, ×3 на ~28-й — параметры `multiplier_growth_rate`,
  `growth_curve` в админке).
- **«Забрать» доступна сразу после ×1.00** (не ждёт первого уровня).
- После забирания шар летит до краха; над кнопкой живая плашка
  «Могли бы забрать: N бонусов (×M)» пересчитывается каждый кадр.
- На результате: «Максимум был ×X (N бонусов)».
- Шар достигает высоты `balloon_max_h` (55% экрана) при `balloon_top_at` (×5)
  и дальше **не упирается в потолок**: висит с покачиванием, а **лестница
  уровней прокручивается** — новые отметки въезжают сверху. Интервалы уровней
  растягиваются множителем `level_gap_scale`.

### 4.3 Уровни и очки
- Уровни через каждые `level_step` коэффициента (по умолчанию ×1:
  ×2, ×3, …, ×13), линии проявляются при подлёте, пройденные остаются яркими.
- После последнего уровня — пунктирное **продолжение по коэффициентам**
  (×14, ×15…, 30 отметок, без очков).
- Очки: `пройденные уровни × points_per_line` + бонус за cashout +
  бонус за активацию бустера. Начисляются и при проигрыше (за уровни).

### 4.4 Бустер в полёте
Сервер до раунда выбирает уровень бустера по распределению `line_loot_prob`
(темы RED/GREEN отдельно, сумма нормализуется). Если шар достиг уровня бустера
**до** забирания — коэффициент умножается на значение бустера
(+ очки `points_xN_bonus`). Иконка 🎁 ждёт на своей линии слева от шкалы.
Любое значение бустера безопасно для экономики — см. математику.

### 4.5 Высотные зоны
| Зона | Порог (админка) | Что меняется |
|---|---|---|
| Земля | до ×2 | небо, облака, площадка, птицы (кадровые), звуки `sfx1-4` |
| Атмосфера | с ×2 | фон `sky-mid` (или видео `trans-mid`), **только самолёты**, звуки sfx |
| Космос | с ×5 | фон `sky-high` (или `trans-high`), тарелки (со свечением), 4 спутника на разных эшелонах и со своей скоростью, звуки `space1-4` |
| Галактика | с ×1000 | адский фон `sky-galaxy` (или `trans-galaxy`), **огненный коэффициент**, джекпот при выводе |

Объекты зон не пересекаются (общий реестр размещения + разведённые полосы
высот). Переходные видео играют один раз; **последний кадр остаётся фоном зоны**.
⚠ При дефолтной математике ×1000 недостижим (вероятность ≈ e^-1263) — для демо
временно ставьте порог галактики 5–10 в админке.

### 4.6 Джекпот
Cashout в зоне галактики → звук `jackpot.mp3` (или синтез-фанфара), салют,
модалка «ДЖЕКПОТ» с **быстрым отсчётом денег от нуля до выигрыша** (~2.6 с).

### 4.7 Пазлы и подарок
- За каждый завершённый раунд — пазлы: `ставка / puzzle_rate` (минимум 1).
- Набрал `gift_threshold` → кнопка «Подарок» → **крутилка как в CS:GO**:
  лента проносится мимо метки с замедлением ~5.5 с, тикает `reel.mp3`;
  выигрышный сегмент **не подсвечивается заранее** (интрига до остановки);
  мелкий выигрыш останавливается «не доезжая» до края, крупный — чуть
  «переезжает». Цвета: 10 ₽ серый, 1000 ₽ золото, 10 000 ₽ алмаз.
- Приз — взвешенный случайный из `gift_prizes` (админ: «сумма:вес»).
  Дефолт: 10 ₽ (1000), 100 ₽ (100), 1000 ₽ (10), 10 000 ₽ (1) → шанс на 10к ≈ 0.09%.
- «Открыть подарок снова» — сразу, если пазлов хватает ещё. Приз демо-начисление.

### 4.8 Лидерборд
- Вкладки **«День»** (очки за сегодня, обнуляются в полночь; живой таймер
  обратного отсчёта рядом с заголовком) и **«Всё время»**. Топ-10, email маскируется
  (`i***@x.com`), админы участвуют, лидер дня помечен 🎁.
- Призы за день — `leaderboard_reward` («место:сумма», дефолт 1 место — 1000 ₽,
  2 — 500 ₽, 3 — 250 ₽), строка призов над списком. По истечении дня, если вы
  на 1 месте — **крутилка итогов дня** с вашим призом и салютом.

### 4.9 История взрывов
Лента последних 10 крахов фишками: < ×2 красные, ×2–9.99 зелёные, ≥ ×10 жёлтые.
Новый взрыв вытесняет самый старый.

### 4.10 Звуки и музыка
- Слоты: капель выбора темы (`theme`), клик, уровень, бустер, cashout, крах,
  музыка полёта (`flight`, до взрыва), фон меню (`ambient`), тиканье барабана
  (`reel`), джекпот (`jackpot`), случайные по зонам (`sfx1-4` / `space1-4`).
- Файлов нет — звуки синтезируются WebAudio; музыка без файла просто молчит.
- Кнопка «Музыка» (Настройки) глушит фон, выбор запоминается; фон и музыка
  полёта **никогда не накладываются** (флаг полёта блокирует фон).

### 4.11 Настройки
Шестерёнка в верхнем баре: смена темы, музыка, +100 бонусов, правила,
«К выбору темы», админам — «Параметры». Верхний бар — только бонусы, очки,
пазлы (+Подарок) и Настройки. Новая модалка автоматически закрывает предыдущую.

### 4.12 Админ-панель
Вход admin@mail.com/12345678 → «Параметры». Вкладки:
- **Параметры** — удобная форма по разделам: математика краха, рост коэффициента,
  уровни и очки, пазлы/подарок, ставки/бустеры, зоны, случайные звуки, призы
  лидерборда + ручной JSON и кнопки «Сохранить»/«Вернуть текущие».
- **Пользователи** — email, баланс, очки, пазлы, раунды.
- **Раунды** — история всех игр.
Изменения применяются **со следующего раунда, без перезапуска** (POST /api/config
пишет config.json; GET перечитывает его с диска — программист может править
файл, игроку достаточно F5).

### 4.13 Честность (provably fair, упрощённо)
До полёта публикуется `SHA-256(seed | roundId | crashPoint)`; seed раскрывается
после краха, кнопка «Проверить seed» пересчитывает хеш в браузере. Клиент не
знает точку краха до взрыва — досрочный «честный» cashout по известному краху
невозможен. Режим разработчика: `dev_seed` в конфиге — детерминированный крах.

## 8. Математическая модель и почему она работает

### 8.1 Точка краха
```
u ~ Uniform(0,1);  E = -ln(1-u)  ~ Exp(1)
crash = clamp((1 + E/alpha) * edge, min, max)
```
Параметры: `alpha=1.2`, `edge=0.95`, `min=1.0`, `max=1000`.
Превышение max — мгновенный крах (вероятность пренебрежима при max=1000).

**Свойства.** Для `x ≥ edge`: `P(crash ≥ x) = P(E ≥ alpha(x/edge - 1)) = e^(-alpha(x/edge - 1))`.
- медиана: `(1 + ln2/1.2)·0.95 ≈ ×1.50`
- P(crash ≥ 2) ≈ 0.27, P(crash ≥ 5) ≈ 0.006, P(crash ≥ 10) ≈ 1.6·10⁻⁵, P(crash ≥ 1000) ≈ e⁻¹²⁶³ ≈ 0

### 8.2 Почему игра не уходит в минус при ЛЮБОМ бустере
Игрок, забирающий при коэффициенте C, выигрывает `ставка × C`, если `crash ≥ C`,
и теряет ставку иначе:

```
EV(C) = C · P(crash ≥ C) = C · e^(-alpha(C/edge - 1))
```

Производная: `EV'(C) = e^(...)(1 - alpha·C/edge)` — обращается в ноль при
`C = edge/alpha = 0.79`, что **меньше минимального краха 1.0**. Значит, на всём
допустимом диапазоне `C ≥ 1` функция EV убывает, а максимум достигается при
C = 1: `EV(1) = 1`. Итог:

> **EV(C) ≤ 1 для любого коэффициента забирания, при любом бустере.**
> Равенство 1 только при мгновенном заборе ×1.00 (возврат ставки). Каждая
> секунда ожидания строго убывает в ценности: `EV(2) ≈ 0.40`, `EV(5) ≈ 0.029`.

Бустер лишь масштабирует C (`C = booster × m`), поэтому разрешены любые
значения (×1…×1000) — экономика не ломается по построению. House edge
встроен в `edge < 1`, оператор в плюсе на дистанции автоматически.

### 8.3 Рост коэффициента
`m(t) = 1 + g·t^p` (g=0.005, p=1.8): нулевая скорость в старте (шар «разгоняется»),
разгон к середине; округление до 0.01 на сервере и клиенте. Сервер считает от
`System.nanoTime`, cashout всегда пересчитывается сервером — клиентские часы
результат не определяют.

### 8.4 Уровни и очки
Уровень i пройден при `m ≥ 1 + i·level_step`. Очки раунда:
`passed·points_per_line + (cashout ? cashout_bonus : 0) + (бустер ? xN_bonus : 0)`.
Очки за уровни начисляются даже при краше — стимул «долетать хотя бы до уровня».

### 8.5 Позиция бустера
Дискретное распределение по `line_loot_prob` (нормализация суммы не требуется):
`P(line = i) = p_i / Σp`. Вероятности убывают с высотой — чаще маленькие радости,
редко большой сюрприз.

### 8.6 Подарок
Взвешенный случай: `P(приз a_i) = w_i / Σw`. Дефолт: 10 ₽ — 90.0%, 100 ₽ — 9.0%,
1000 ₽ — 0.90%, 10 000 ₽ — 0.09%. Ожидание подарка ≈ 26 ₽ на каждые 100 пазлов
(1 пазл ≈ 0.26 ₽) — масштаб настраивается админом через веса.

### 8.7 Дневной лидерборд
`dayPoints` сбрасываются при первом начислении очков нового календарного дня
(по часовому поясу сервера); `endsAt` = следующая полночь — клиентский таймер
лишь отображает разницу.

## 9. Хранение и персистентность

- `users.json` — все аккаунты (пароли SHA-256, для прототипа; в проде нужен
  bcrypt/salt), балансы, очки (всего и за день), пазлы, последний приз, токены.
  Переживает перезапуск; удаление файла = полный сброс (админ пересоздастся).
- `config.json` — конфиг после первого сохранения админом; GET /api/config
  перечитывает его с диска (правка файла применяется без перезапуска).
- Раунды и история — в памяти (прототип), история игр пополняется ботами при
  пустой базе.

## 10. Ограничения прототипа (честно)

- Один сервер-процесс, состояние раундов в памяти (перезапуск теряет незавершённые
  раунды; очки/баланс — нет, они в users.json).
- Начисление реальных рублей (призы подарка/лидерборда) не подключено — демо.
- Пароли без соли; токены бессрочные; нет rate-limit и HTTPS.
- WebSocket-мультиплеер, живой рейтинг в полёте, турнирные таблицы и апсейл
  «Закрепи успех» — дополнительные модули ТЗ, в MVP не входили.

real-time — polling `/api/round/state` (250 мс), сервер авторитетен
(cashout пересчитывается от серверного `nanoTime`).

## 13. Математическая модель: обоснование и генерация случайности

### 13.1 Модель краха
`crash = clamp((1 + Exp(1)/alpha) · edge, min, max)` (см. раздел 8).
**Обоснование подхода.** Экспоненциальное семейство — стандарт индустрии
crash-игр: (а) монотонно убывающая плотность — короткие раунды частые,
длинные редкие, что даёт ритм «быстро-азартно» и вовлечённость; (б) свойство
памятиlessness делает аналитику прозрачной; (в) параметр `edge < 1` встраивает
house edge напрямую в распределение, а не в последующие поправки; (г) доказано
(раздел 8.2), что EV любого cashout-коеффициента ≤ 1 — экономика неотрицательна
при любых настройках бустеров.

### 13.2 Генерация случайных событий
- **SecureRandom** (CSPRNG) для краха, seed, позиции бустера, приза подарка.
- **Provably fair (упрощённый)**: до раунда публикуется
  `SHA-256(seed | roundId | crashPoint)`; seed раскрывается после краха,
  клиент пересчитывает хеш. Сервер не передаёт crashPoint до взрыва.
- **Режим разработчика** (`dev_seed`): крах детерминирован —
  `u` из SHA-256(dev_seed | roundId), воспроизводимость для отладки/демо.
- Позиция бустера — дискретное распределение `line_loot_prob` (нормализация
  суммы не требуется); приз подарка — взвешенный случай `gift_prizes`.

### 13.3 Расчёт выигрыша и очков
```
win    = bet × m(t_cashout) × booster   (округление вниз, только при cashout)
points = passed·points_per_line + (cashout? cashout_bonus:0) + (boost? xN_bonus:0)
```
Cashout-сервер пересчитывает от собственного монотонного времени; прошедшие
уровни фиксируются момент пересечения `m ≥ 1 + i·level_step`.

### 13.4 Влияние параметров на результат
| Параметр | Рост ↑ | Эффект |
|---|---|---|
| alpha | больше | крахи ниже/чаще, раунды короче |
| edge | →1 | матожидание убыточности оператора падает (≤0.999) |
| min_crash_multiplier | ↑ | гарантированная длительность раунда растёт |
| max_multiplier | ↑ | потолок редких «легендарных» крахов (×1000) |
| growth_rate / growth_curve | ↑ | коэффициент быстрее/медленнее во времени (не влияет на экономику — только на темп) |
| level_step | ↑ | уровни реже → очки за раунд меньше, cashout позже |
| altitude.high/galaxy | ↓ | зоны/джекпот достижимее (важно при медленном росте) |
| gift веса | сдвиг к крупным | матожидание приза растёт (контроль оператора) |

Экономика (EV ≤ 1) не зависит от темповых параметров — только от формы
распределения краха.

## 14. Инструкция по настройке параметров

### 14.1 Где настраивать
1. **Админ-панель** (вход `admin@mail.com` / `12345678` → Настройки →

| Параметр | Назначение | Допустимые | Применение |
|---|---|---|---|
| is_active | вкл/выкл игру | true/false | мгновенно (старт раунда) |

### 15.1 Реализовано (обязательные сценарии 1–5 полностью)
- Стартовый экран с двумя темами (12/9 уровней), площадкой, облаками,
  птицами (покадровая анимация, случайные виды/число/моменты);

- Полёт: рост коэффициента, уровни (привязка по верхушке шара, штрихи

  «могли бы забрать» (live и итог), взрыв (покадровый), очки;
- Crash: ставка сгорает, точка краха в истории, очки за уровни сохраняются;
- Бустер: случайная позиция, ×2/×3/×4 (и любые), доп. очки, расчёт с бустом;
- Конфигурация без кода: админ-форма + JSON + config.json, горячее применение;
- Дополнительно: регистрация/вход + админ-аккаунт, админ-панель

  пазлы и подарок с взвешенными призами, джекпот галактики с отсчётом денег,
  4 высотные зоны с объектами (самолёты/тарелки/спутники, без пересечений),
  переходные видео с заморозкой последнего кадра, зональные звуки,
  музыкальная система без наложений, provably fair (хеш + проверка),

### 15.2 Известные ограничения (прототип)
- Состояние раундов и история — в памяти одного процесса; перезапуск сервера
  прерывает незавершённые раунды (баланс/очки/пазлы в users.json сохраняются).
- Хеш паролей — SHA-256 без соли; токены бессрочные; нет rate-limit/HTTPS —
  только для закрытого демо.
- Начисление реальных денежных призов (подарок, лидерборд) не подключено —
  демонстрация механики.
- Real-time — polling 250 мс (не WebSocket); единый демо-пользователь на
  браузер, мультиплеер-столы не реализованы.
- Скриптовые события (боты) в истории — статичная выборка при старте.
- Сохранение игры mid-flight (восстановление раунда) не реализовано —
  доп. модуль ТЗ.
